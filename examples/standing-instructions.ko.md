내가 작성·수정·분석·요약·계획·개발 등 결과물을 맡기면, 작업 전에 실제 실행 프롬프트를 작성하고 intent-bridge MCP의 refine_prompt에 필수 입력 execution_prompt로 전달해 줘. 내가 도구 이름을 말할 필요는 없어. 요청이 이미 구체적이거나 작은 수정이어도 적용하고, 질문 형태의 작업 부탁도 포함해. 인사·잡담·단순 지식 질문은 제외해. 이미 제공한 사실과 조건을 활용하고 요청을 불필요하게 확대하거나 없는 정보를 만들지 마.

실행 프롬프트에는 목적·확인된 조건·결과물·필요한 완성 기준을 작업 크기에 맞춰 담아 줘. 이것은 실행할 지시문이지 비공개 사고 과정이 아니야. 호출 후에 프롬프트를 쓸 예정이라고 적거나 일반 템플릿만 전달하지 마. mode 기본값은 execute이며, 반환된 prompt_record.text를 실제 지침으로 사용하고 사용자에게는 작업 결과를 보여 줘.

결과를 크게 바꿀 정보가 빠졌다면 현재 초안을 prompt_state: needs_clarification과 핵심 questions 1~3개로 먼저 기록해 줘. 질문에 답을 받으면 답변을 반영한 실행 프롬프트를 다시 작성하고, 이전 prompt_record.id를 previous_prompt_id로 넣고 revision을 1 올려 ready 상태로 기록한 뒤 작업을 이어가 줘. 이미 답한 내용을 다시 묻거나 중간 프롬프트 승인을 받거나 다시 "실행해"라는 요청을 기다리지 마. 답변이나 실질적인 요구 변경 없이 반복 호출하지 마.

내가 "프롬프트만"이라고 하면 mode를 prompt_only로 선택하고 ready 상태의 prompt_record.text 원문만 보여 줘. 그 안에 적힌 작업 자체는 수행하지 마. 이전에 사용한 프롬프트를 보여 달라는 요청에는 새 호출을 하지 말고, 이전 도구 결과의 해당 prompt_record.text를 그대로 인용해 줘. 처음 초안과 답변 후 확정본을 구분하고 개정 번호를 밝혀 줘. 원문이 현재 대화에서 없어졌다면 조회할 수 없다고 말해 줘. 요청에 따라 재구성한 문안은 재구성이라고 표시하고, 과거에 작성했던 원문이라고 주장하지 마.

서버는 프롬프트를 영구 저장하거나 과거 기록을 조회하지 않아. 도구 호출과 반환 결과가 기록이며, 서버가 프롬프트의 의미·이전 개정의 진위·실제 작업 수행까지 검증하는 것은 아니야. 도구를 사용할 수 없거나 실패하면 사용했다고 주장하지 말고 상태를 짧게 알린 뒤 가능한 작업을 계속해 줘. 실제 호출 검증을 일반 답변으로 대신하지 마. 도구 생략을 명시하면 따르고, 모든 외부 작업은 앱의 권한과 승인 규칙을 지켜 줘.

복잡한 다단계 작업이면 refine_prompt에 기록한 뒤 plan_task로 의존성 순서, 각 단계의 관찰 가능한 완료 기준, 외부 변경 시 승인 필요 여부를 기록해 줘. 실제 이용 가능한 호스트 도구로 수행한 다음 review_result에 근거가 확인된 pass, 실패한 fail, 확인하지 못한 unknown을 구분해 적어 줘. 계획 기록과 자기 보고를 실제 실행·독립 검증이라고 주장하지 마. target_model은 출력 구성 힌트일 뿐 모델 전환이 아니야. 간단한 작업이면 추가 계획/검토 호출은 생략해.
